# Set Reminders - LLM Enhanced

[![Open your Home Assistant instance and show the blueprint import dialog with a specific blueprint pre-filled.](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2FTheFes%2Fha-blueprints%2Fblob%2Fmain%2Freminder%2F2_voice_reminder_llm_enhanced.yaml)

Using this blueprint you can create an automation to set reminders. The request is caught by local trigger sentences, so the voice pipeline can use the local Home Assistant conversation agent (or an LLM with local preference), and the LLM doesn't need access to your house.

An [AI Task](https://www.home-assistant.io/integrations/ai_task/) call (`ai_task.generate_data`) with structured output determines the text, the recipients (a select, so only configured recipients can be returned), the date and the time. It also provides a question for missing information and a confirmation, both in the language of the request.

## Follow-up questions

An AI Task can't have a conversation, so the follow-up questions are handled by the automation:

* **On a voice satellite**: when something is missing, Assist gives no response, and a second run of the automation (started with the `voice_reminder_follow_up` event) waits until the satellite is idle and asks the question with `assist_satellite.ask_question`. Your answer is added to the conversation and the AI Task is used again. This repeats until everything is known, or the maximum number of questions is reached. The confirmation is announced on the satellite
* **In text chat** (or with the maximum number of questions set to 0): the response contains the question, and you need to say the complete request again including the answer

## Who is "me"?

"Me" refers to the recipient whose person is linked to the user talking to Assist. When you use a voice satellite, there is no user, so "me" refers to the recipient which has that satellite set (when only one recipient has it). Otherwise the recipients are missing, and Assist asks who should be reminded.

## Requirements

* Home Assistant 2025.7 or newer
* An AI Task entity. You can select it in the blueprint, or set a preferred AI Task entity in Home Assistant
* A todo list which supports due dates with a time and descriptions. The [Local To-do](https://www.home-assistant.io/integrations/local_todo/) integration works fine, preferably create a separate list for the reminders
* An automation based on the [Send Reminder (version 2)](0_voice_send_reminder_v2.md) blueprint to send the reminders

## Limitations

* The sentence has to match one of the trigger sentences
* The trigger sentences and the responses which are not generated by the AI need to be translated when you use another language than English
* Follow-up questions only work on Assist satellites which support `ask_question` (like the Home Assistant Voice Preview Edition)

## Recipients

The recipients are set with an object selector, with these fields for each recipient:

|Field|Description|
|---|---|
|Name|The name of the recipient, for example `Martijn`. Can also be a group, like `The kids`|
|Other names or description|Comma separated, for example `dad, father`. Used to recognize the recipient|
|Person|Optional. Used to know who "me" is (the user linked to the person), and the Assist satellites are only used when this person is home|
|Notify entities|The notify entities which receive the reminder, for example the notify entity of the Companion app on your phone|
|Assist satellites|Optional. The reminder is announced on these satellites when the person is home (or always when no person is set)|

In YAML it looks like this:

```yaml
- name: Martijn
  aliases: dad
  person: person.martijn
  notify:
    - notify.pixel_10_pro
  satellites:
    - assist_satellite.office
- name: Marleen
  person: person.marleen
  notify:
    - notify.iphone_van_marleen
```

## How the reminders are stored

The reminder is added to the todo list with the text as summary and the moment as due date and time. The recipients are stored in the description, one line per recipient with the entities to use, for example:

```
Martijn: notify.pixel_10_pro, assist_satellite.office, person.martijn
```

The [Send Reminder (version 2)](0_voice_send_reminder_v2.md) automation reads this description, so it doesn't need an LLM or its own list of recipients. Changing the recipients in the blueprint doesn't change reminders which were already set.

## Blueprint settings

|Setting|Description|
|---|---|
|ToDo list|The list to store the reminders in|
|Recipients|See above|
|Trigger sentences|Need a `{query}` wildcard. Default: `remind {query}` and `(set\|create\|make\|add) a reminder [for] {query}`|
|Maximum number of follow-up questions|Default 3, set to 0 to never ask|
|AI Task entity|Leave empty to use the preferred AI Task entity|
|Instructions for the AI|`{{ conversation }}` is the request (and the follow-up questions and answers), `{{ speaker }}` the recipient who is speaking (if known), `{{ recipient_desc }}` the recipients with their other names|
|Information missing|Used in text chat, or when no more questions may be asked. `{question}` is the question for the missing information|
|No answer on the follow-up question|Announced when the satellite didn't hear an answer|
|Error response|Used when the AI Task fails, or the reminder could not be stored|

```yaml
trigger:
  - "herinner {query}"
  - "(zet|maak) een herinnering [voor] {query}"
response_missing: "{question} Zeg je hele verzoek nog een keer, inclusief dit."
response_no_answer: Ik heb geen antwoord gehoord, dus ik heb de herinnering niet ingesteld
response_error: Sorry, het is niet gelukt om de herinnering in te stellen
```
